# 청우해장 홈페이지

대구 중구 남성로 11 · 한식당 청우해장의 다국어 홈페이지입니다.
GitHub Pages 로 그대로 서비스됩니다 — 별도 서버도, 도메인 구매도 필요 없습니다.

**주소** https://hwanman2.github.io/weco/cheongwoo/

| 언어 | 파일 | 대상 |
|---|---|---|
| 한국어 | `index.html` | 국내 손님 · 네이버 검색 |
| English | `en.html` | 영어권 관광객 |
| 日本語 | `ja.html` | 일본 관광객 |
| 简体中文 | `zh.html` | 중국 본토 |
| 繁體中文 | `tw.html` | **대만 · 홍콩** |

---

## 1. 내용을 고치는 방법

HTML 을 직접 고치지 마세요. `src/` 안의 데이터 파일을 고치고 다시 빌드하면
다섯 개 언어가 한 번에 맞춰집니다.

```bash
cd cheongwoo
node build.mjs        # Node 18 이상이면 그대로 실행됩니다. 설치할 패키지 없음.
```

| 무엇을 바꾸려면 | 어느 파일을 |
|---|---|
| 전화번호 · 주소 · 영업시간 · 좌표 · 네이버 예약 링크 | `src/store.mjs` |
| 메뉴 이름 · 설명 · 가격 | `src/store.mjs`(가격) + `src/i18n.mjs`(이름·설명) |
| 한국어/영어/일본어/중국어 문안 | `src/i18n.mjs` |
| 대만(번체) 문안 | `src/i18n.tw.mjs` |
| 약전골목·근대골목 이야기, 주변 관광지 | `src/hood.mjs` |
| 광고 픽셀 ID | `assets/config.js` (빌드 불필요) |
| 디자인 | `assets/site.css` (빌드 불필요) |

빌드하면 `sitemap.xml` 도 같이 다시 만들어집니다.

## 2. 지금 바로 채워야 할 값

`src/store.mjs` 에 비어 있는 항목입니다. **비어 있어도 사이트는 정상 동작합니다** —
채우면 링크가 「검색 결과」가 아니라 「그 가게 페이지」로 바로 꽂힙니다.

```js
naverPlaceId:    '',   // 네이버 플레이스 ID
googleCid:       '',   // 구글 비즈니스 프로필 CID
naverBookingUrl: '',   // 네이버 예약 URL → 「네이버 예약」 버튼이 생깁니다
```

**네이버 플레이스 ID 찾는 법**
네이버지도에서 「한식당 청우해장」을 검색해 가게를 클릭하면 주소창이
`map.naver.com/p/entry/place/`**`1234567890`** 형태가 됩니다. 굵은 숫자만 넣으세요.

**구글 CID 찾는 법**
구글지도에서 가게를 열고 「공유 → 링크 복사」 하면 `maps.app.goo.gl/...` 가 나옵니다.
그 링크를 브라우저에서 열면 주소창에 `?cid=`**`1234567890`** 이 보입니다.
그 숫자입니다. (구글 비즈니스 프로필이 아직 없으면 먼저 등록하세요 — 무료입니다.)

> 이 두 값은 제가 대신 찾으려 했지만, 작업 환경의 네트워크가 네이버지도와
> 구글지도 접속을 막고 있어 확인하지 못했습니다. 사장님 폰으로 30초면 됩니다.

**이미 넣어 둔 값**
- 카카오맵 플레이스 ID `983201124` (확인 완료)
- 네이버 블로그 `blog.naver.com/zzyy004` (공식 블로그로 확인)
- 인스타그램 `instagram.com/chungwoo.official` — 검색으로 찾은 계정입니다.
  **공식 계정이 맞는지 한 번만 확인해 주세요.** 아니면 `src/store.mjs` 에서 지우면 됩니다.

## 3. 사진 — 특히 메인 사진

지금 홈페이지 첫 화면은 **매장 외관 사진**입니다. 위코컴퍼니가 시공·촬영한
매장 사진 10장(`../images/cheongwoo-01.jpg` ~ `-10.jpg`)만 있고
**음식 사진이 하나도 없기 때문**입니다.

식당 홈페이지 첫 화면은 음식 사진이 가장 강합니다. 사진만 구하면 **두 줄**로 바뀝니다.

### 음식 사진 넣는 법

1. 사진을 `weco/images/` 에 넣습니다 — 예: `cheongwoo-food-01.jpg`
   (가로 1600px 이상, 1장당 500KB 이하 권장)
2. `src/store.mjs` 의 `hero` 를 고칩니다:
   ```js
   export const hero = {
     src: 'images/cheongwoo-food-01.jpg',
     kind: 'food',              // ← 'food' 로 두면 글씨 뒤 어둠이 왼쪽으로 쏠려
     position: 'center 55%',    //   오른쪽 음식이 안 가려집니다
     width: 1600, height: 1067,
   };
   ```
3. 메뉴별 사진도 같은 방식으로 `menu` 배열의 `img: null` 을 채웁니다.
4. `node build.mjs`

### 네이버에서 다운받아 쓰는 건 — 출처를 나눠서 봐야 합니다

**써도 되는 것**
- **스마트플레이스에 사장님이 직접 올린 업체 사진.** 가게가 저작권자입니다.
  네이버 이미지 검색에서 `ldb-phinf.pstatic.net` 로 시작하는 주소가 이것들입니다.
  실제로 「한식당 청우해장」 이름으로 등록된 사진이 여러 장 있습니다.
  스마트플레이스 관리자 화면에서 **원본을 그대로 내려받는 게 가장 깨끗합니다.**
- 공식 블로그(`blog.naver.com/zzyy004`)에 가게가 직접 올린 사진.
- 사장님 폰에 있는 원본.

**쓰면 안 되는 것**
- **손님·블로거가 쓴 후기 글의 사진.** 찍은 사람에게 저작권이 있습니다.
  가게 홈페이지는 영리 목적이라 무단 사용 시 저작권 문제가 됩니다.
  실제로 국내에서 분쟁이 자주 나는 유형입니다.
  꼭 쓰고 싶은 사진이 있으면 블로거에게 댓글로 사용 허락을 받으세요.
  (대부분 흔쾌히 허락해 주고, 그 자체가 홍보가 됩니다.)

> 제가 직접 내려받아 넣지는 못했습니다. 작업 환경의 네트워크가
> `pstatic.net`(네이버 이미지 서버) 전체를 막고 있어 접근이 안 됩니다.
> 사장님이 스마트플레이스에서 원본을 받아 주시면 제가 바로 넣겠습니다.

### 새로 찍는다면 (이게 제일 낫습니다)

메인 사진 한 장에 쓸 컷:
- **갈비탕을 위에서 45도로**, 갈비가 쌓인 게 보이게. 김이 살아 있을 때.
- **가로(landscape) 프레임**으로. 세로 사진은 첫 화면에 안 맞습니다.
- 오른쪽에 그릇, 왼쪽은 상판이 비게 — 그 빈자리에 글씨가 올라갑니다.
- 매장 창가 자연광. 조명 안 만져도 됩니다. 낮 12시 전이 제일 좋습니다.
- 매운갈비찜은 **위에서 수직으로**, 냄비 가득 찬 게 보이게 한 장 더.

폰으로 찍어도 충분합니다. 중요한 건 카메라가 아니라 각도와 빛입니다.

### 사진을 넣거나 바꾼 뒤에는 `npm run images` 한 번

원본 JPEG 은 한 장에 300KB 가 넘습니다. 휴대폰 손님도 그걸 통째로 받으면
첫 화면이 늦게 뜹니다. `npm run images` 를 돌리면 사진마다 360·720·1080·1600px
AVIF·WebP 를 `images/opt/` 에 만들고 `images/manifest.json` 에 목록을 씁니다.
그 다음 `node build.mjs` 가 그 목록을 읽어 `<picture>` 로 내보냅니다.

```bash
npm install          # 처음 한 번 (sharp 설치)
npm run images       # 사진이 바뀔 때만
node build.mjs       # 늘 하던 것
```

- `build.mjs` 자체는 여전히 **의존성이 0개**입니다. manifest 가 없으면 예전처럼
  원본 `<img>` 로 냅니다. sharp 는 `tools/optimize-images.mjs` 만 씁니다.
- `images/opt/` 와 `manifest.json` 은 **커밋합니다.** GitHub Pages 가 그대로 씁니다.
- 원본 JPEG 은 지우지 마세요. 카카오톡·네이버 공유 미리보기가 원본을 씁니다.
- `main` 에 푸시하면 GitHub Actions 가 위 세 줄을 자동으로 돌리고 배포합니다
  (`.github/workflows/deploy.yml`). 로컬에서 빌드를 잊어도 안전합니다.

## 4. 광고 픽셀 붙이기

`assets/config.js` 하나만 고치면 됩니다. 값이 비어 있으면 그 플랫폼 스크립트는
아예 로드되지 않으므로, 쓰는 것만 채우면 됩니다.

```js
metaPixelId: '1234567890',          // 메타(페이스북·인스타) 픽셀
googleAdsId: 'AW-1234567890',       // 구글 광고
googleAdsLabels: { call:'AbC...', directions:'DeF...', reserve:'GhI...' },
ga4Id: 'G-XXXXXXXXXX',              // 구글 애널리틱스 4
```

자세한 전환 설계와 캠페인 운영법은 **`MARKETING.md`** 를 보세요.

### 코드가 알아서 해 주는 것

| 장치 | 하는 일 | 왜 |
|---|---|---|
| 세션당 1회 집계 | 전화·길찾기·예약은 한 방문에 1건만 전환으로 보냄 | 같은 사람이 세 번 눌러도 손님이 셋이 되지는 않습니다. 그대로 보내면 알고리즘이 전환 가치를 세 배로 잘못 배웁니다 |
| 캠페인 정보 동봉 | 모든 전환에 `utm_*` · `gclid` · `fbclid` 를 붙여 전송 | GA4 에서 「어느 광고가 전화를 울렸나」가 보입니다 |
| 내부 트래픽 제외 | 지정한 기기는 픽셀을 아예 로드하지 않음 | 사장님·직원 방문이 모수를 오염시키지 않게 |
| `eventID` 부여 | 전환마다 고유 ID | 나중에 메타 전환 API 를 붙일 때 중복 집계 방지 |
| beacon 전송 | 페이지를 떠나도 측정이 유실되지 않음 | 전화 앱이 뜨면서 전송이 끊기는 것 방지 |

**내부 트래픽 제외** — 사장님·직원·대행사 각자 폰에서 **딱 한 번** 열어 주세요.

```
https://hwanman2.github.io/weco/cheongwoo/?cw_optout=1     ← 제외 켜기
https://hwanman2.github.io/weco/cheongwoo/?cw_optout=0     ← 끄기
```

### 잘 붙었는지 확인하는 법
- `config.js` 에서 `debug: true` 로 바꾸면 브라우저 콘솔에 이벤트가 찍힙니다.
- 메타: Chrome 확장 **Meta Pixel Helper**
- 구글: **Google Tag Assistant** 또는 GA4 실시간 보고서
- 전화 버튼을 연속으로 3번 눌러 보세요. **전환은 1건, 나머지는 `_repeat`** 로
  찍히면 정상입니다.

## 5. 구글·네이버에 검색되게 하기

**결론부터: 됩니다.** GitHub Pages 로 올린 사이트도 일반 웹사이트와 똑같이
구글·네이버에 색인됩니다. 다만 아래 순서를 밟아야 합니다.

### ① 먼저 `main` 브랜치에 합쳐야 합니다 ★ 가장 중요
GitHub Pages 는 **`main` 브랜치만** 서비스합니다. 지금 이 홈페이지는
`claude/cheongwoo-haejang-website-n1gwvt` 브랜치에 있어서, 합치기 전까지는
주소로 들어가도 404 가 뜹니다. 검색은 그 다음 문제입니다.

합치고 1~2분 뒤 `https://hwanman2.github.io/weco/cheongwoo/` 가 열리면 성공입니다.

### ② 구글 서치콘솔 등록
1. search.google.com/search-console → 속성 추가 → **URL 접두어**
   → `https://hwanman2.github.io/weco/cheongwoo/`
2. 소유확인 방법에서 **HTML 태그**를 고르면 `content="..."` 코드를 줍니다.
3. 그 코드를 `src/store.mjs` 의 `googleSiteVerification` 에 넣고 `node build.mjs`
4. main 에 푸시 → 서치콘솔에서 「확인」
5. 좌측 **Sitemaps** 에 `https://hwanman2.github.io/weco/cheongwoo/sitemap.xml` 제출
6. **URL 검사** 도구에 한국어 페이지 주소를 넣고 「색인 생성 요청」
   — 이걸 하면 며칠이 몇 시간으로 줄어듭니다. 5개 언어 각각 해 주세요.

### ③ 네이버 서치어드바이저 등록
같은 방식입니다. 코드는 `src/store.mjs` 의 `naverSiteVerification` 에.
사이트맵도 같이 제출하세요.

> 소유확인 코드는 **`assets/config.js` 가 아니라 `src/store.mjs`** 에 넣어야 합니다.
> `config.js` 는 브라우저에서 실행되는 파일이라 거기 적으면 `<meta>` 태그가
> 되지 않습니다. 검색엔진은 HTML 소스만 봅니다.

### ④ 지도 서비스에 홈페이지 주소 걸기 — 실제로 제일 큰 한 방
- **구글 비즈니스 프로필**(business.google.com) 「웹사이트」 칸
- **네이버 스마트플레이스** 「홈페이지」 칸

식당은 사람들이 홈페이지를 검색해서 오는 게 아니라 **지도에서 찾아 홈페이지로
들어옵니다.** 그리고 구글은 비즈니스 프로필과 홈페이지의 정보(주소·전화·영업시간)가
일치하면 같은 가게로 묶어 신뢰도를 올립니다. 홈페이지의 구조화 데이터를
플레이스와 똑같이 맞춰 둔 이유가 이것입니다.

### 얼마나 걸리나
- 색인 요청까지 하면 **보통 며칠**, 늦어도 2~3주 안에 뜹니다.
- 「청우해장」 같은 상호 검색은 금방 올라옵니다.
- 「대구 갈비탕」 같은 경쟁 키워드는 몇 달 걸립니다. 이건 정상입니다.

### 알아 둘 것 두 가지

**robots.txt 는 지금 위치에서 효력이 없습니다.**
검색엔진은 `hwanman2.github.io/robots.txt`(도메인 최상단)만 읽습니다.
지금 파일은 `hwanman2.github.io/weco/robots.txt` 라 무시됩니다.
사이트맵은 서치콘솔에 직접 제출하면 되니 실무상 문제는 없습니다.
꼭 필요하면 `hwanman2.github.io` 라는 이름의 저장소를 따로 만들어 거기에 두세요.

**주소가 위코컴퍼니 사이트 아래에 있습니다.**
`hwanman2.github.io/weco/cheongwoo/` 는 인테리어 회사 사이트의 하위 폴더입니다.
- 장점: 위코 사이트가 쌓아 둔 신뢰도를 일부 물려받습니다. 지금 당장은 유리합니다.
- 단점: 검색엔진 입장에서 「청우해장」은 독립된 사이트가 아닙니다.
- **도메인을 사기로 하셨으니 이 단점은 곧 없어집니다.**
  `src/store.mjs` 의 `customDomain` 한 줄만 채우면 주소·사이트맵·구조화
  데이터·CNAME 이 전부 새 도메인으로 바뀝니다. 구매 절차와 DNS 설정은
  **`DOMAIN.md`** 를 보세요.

## 6. 구조

```
cheongwoo/
├─ build.mjs           빌드 스크립트 (의존성 없음)
├─ src/
│  ├─ store.mjs        매장 정보 원본 — 전화·주소·시간·메뉴·좌표
│  ├─ i18n.mjs         한국어/영어/일본어/중국어 문안
│  ├─ i18n.tw.mjs      대만(번체) 문안
│  └─ hood.mjs         약전골목·근대골목 역사와 주변 관광 코스
├─ assets/
```

## 9. 이 저장소는 공개입니다

GitHub Pages 로 서비스하려면 저장소가 공개여야 합니다. 즉 `README.md` 와
**`MARKETING.md`(키워드 분석·광고 운영 계획)도 누구나 볼 수 있습니다.**

경쟁 업체에 보이면 곤란한 내용이면 `MARKETING.md` 는 저장소에서 빼고
따로 보관하시는 편이 낫습니다. (홈페이지 동작에는 아무 영향이 없습니다.)

저장소 최상단에 이미 `.nojekyll` 이 있어서 `.md` 파일이 웹페이지로 자동
변환되지는 않고, 사이트맵에도 넣지 않았습니다. 다만 파일 주소를 직접 치면
누구나 읽을 수 있습니다.
